# v0.1.0 試作仕様

この文書は、ブラウザで遊べる単一ラウンド版の挙動を記録する。完成版の構想と未決定事項は[ゲームデザイン](game-design.md)と[開発ロードマップ](roadmap.md)を参照。

## 採用したルール

- 5対5。人間とAIは同じ移動、照準、攻撃意思、設置のコマンドを渡す。移動と照準は独立している。
- 通常攻撃は方向・射程・視界・遮蔽物から有効な敵1人を選び、攻撃入力中のみダメージを与える。現在の対象に選択上の優先度を付け、対象が無効になれば再選択する。
- 通常シールドの超過ダメージがHPに届く。被弾の3秒後からシールドが毎秒20%回復する。HPの回復は自軍本部で行う。
- 装置を明示的に設置し、起動完了後に所有権が移る。継続得点の主な発生源は拠点保持。敵は攻撃、占領範囲への進入、設置チームを追い払うことで起動を妨害できる。
- 敵の表示は生存中の味方全員の視界を合成する。攻撃の成立には攻撃者自身からの見通しが必要。

## 試作用の調整値

| 項目 | v0.1.0での扱い |
| --- | --- |
| 戦場 | 30×17タイル、左右対称。南北の本部、A・B・Cの3拠点、外周と遮蔽物の間を通る迂回路 |
| 試合 | 5分で1ラウンド。開発用にURLの `round` で短縮。60 Hzのシミュレーション時間で進行 |
| キャラクター | HP 100、シールド100、移動速度151、射程165、視界235ワールド単位。1タイルは32単位 |
| 通常攻撃 | 18ダメージ、40ステップ間隔。方向なしの入力では射程内の有効対象を距離と対象維持の補正で選ぶ |
| 被弾・復活 | 自軍本部の半径84以内で、被弾から3秒後に毎秒24 HP回復。死亡時は試合進行に応じて約2〜10秒後に初期位置へ復活 |
| 装置 | 占領半径54。範囲内の設置コマンドで即座に装置を配置。設置側が範囲にいて、敵がいない時間を累積5秒維持すると起動。設置側が2.5秒不在で撤去。両チームが同時に初回の設置を試みたステップでは設置を見送る |
| スコア | 拠点保持1点/秒/拠点、占領完了4点、撃破2点。係争中も既存の所有者に保持点が入る |
| 同点処理 | 時間切れ時にスコア、保有拠点数、撃破数の順で比較し、すべて同数なら引き分け。完成版の同点処理は未決定 |
| 衝突 | ユニットはTilemapの壁に衝突し、他のユニットとはすり抜ける |
| AI | スロットごとに拠点を割り当て、一部のAIは占領後に未確保拠点へ移動。視認した近い敵に照準を向け、射程内で攻撃。タイル経路探索で遮蔽物を迂回し、低HP・低シールド時は本部へ戻る |
| タッチ | タップは対象を自動選択して1回攻撃を試みる。ドラッグで方向指定し、ホールドで継続攻撃。スティックは初期状態で浮動モード |
| ゲームパッド | 最初に認識された標準マッピングのパッドを使用。デッドゾーンに加え、軸だけで切り替える際は一定量以上の入力が5ステップ続く必要がある |

## 実装の境界

`src/rules/` はDOMを使わず、Simpludify CoreのScene、Actor、Motion、CollisionWorld、Tilemapで試合を進める。各ステップで全参加者のコマンドを取得してから移動し、衝突処理後に攻撃、占領、スコアを確定する。同じステップで発生した攻撃は双方に成立する。AIは同じコマンドを生成する入力元として実装する。

`src/web/` はSimpludify Webの固定ステップホスト、ポインター投影、Action入力、仮想スティック・ボタン、ゲームパッドを利用する。カメラは戦場全体を表示し、アスペクト比を維持する。HTMLのHUD・設定画面と描画は試合状態を参照し、勝敗の計算はルール側で行う。再試合ではSceneごと作り直す。

## Simpludifyへの改善候補

- ポインター、キーボード、ゲームパッドの有効な入力元と最終操作を共通APIから取得できると、ハイブリッド端末の入力方式切り替えを各ゲームで実装する量を減らせる。
- 仮想スティックの透明度とボタンラベルを公開描画APIで設定できると、ゲーム側で同じ座標にHTMLを重ねる必要が減る。ジェスチャーとマルチタッチ自体は既存の仮想入力APIで処理している。
- Tilemapの遮蔽物に対する線分・レイの問い合わせがあれば、照準と視界が衝突用地形を直接参照しやすくなる。

実機スマートフォンと物理ゲームパッド、Safari・Firefoxでの互換性、マップとチームのバランスは今後の検証項目。オンライン同期、特殊バリア・肩代わり、設置装置の購入や手動解除、補給線による復活先の選択は完成版の設計課題として扱う。
