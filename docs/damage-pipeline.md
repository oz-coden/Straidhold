# 通常攻撃とダメージ処理

## 共通通常攻撃

試作版の共通通常攻撃は、60Hzの固定ステップで1発10ダメージ、30tick（0.5秒）間隔。入力保持かつ攻撃対象が有効な状態での基準値は20 DPS。基本HPと通常シールドは各100。照準方式、射程、視界、遮蔽物は既存の戦闘ルールに従う。キャラクター固有の攻撃は個別の設計値を使う。

## 処理の順序と責務

1. `DamageRequest` にラウンド内の攻撃識別子、元の攻撃者、元の対象、基礎ダメージを記録する。
2. `DamageContext` に今回の適用先と現在のダメージ量を持たせる。発射を集めた時点で攻撃側の与ダメージ増減を割合ポイントで合計し、基礎ダメージに反映する。適用先の被ダメージ軽減も同種の有効補正を合計して適用する。
3. 特殊処理は **特殊バリア → 肩代わり → 将来追加する特殊処理** の順で明示的に実行する。
4. `resolveDamage` が通常シールドを減らし、超過分をHPに適用する。実減少量、適用先、適用後の値、撃破の有無を `DamageResult` にまとめる。
5. `Battle` が結果を反映し、命中・撃破イベント、与被ダメージ統計、アシスト履歴を更新する。バリアが吸収した実量は `barrierDamage` で区別する。

同tickで攻撃を先に全員分集めるため、そのtickに撃破された攻撃者の発射も同じ攻撃側補正で着弾する。HPが0になった一撃で撃破を確定し、死亡済みの対象への後続命中は記録しない。回復は着弾後に処理し、実際に回復が始まった時点でアシスト履歴をクリアする。

## 特殊バリアと肩代わり

バリアは残容量まで吸収し、破壊した一撃の超過分を無効にする。バリアへの命中も回復待機時間をリセットし、実際の吸収量だけを命中・与被ダメージに記録する。

肩代わりはバリア判定を通過した一次ダメージを基準にする。各タンクへ同じ一次ダメージの50%ずつを割り当て、元の対象には残りを適用する。処理順はタンクのロスター順。転送されたContextは同じ `DamageRequest` と転送済みの印を持ち、転送先の被ダメージ軽減・特殊バリア・通常シールド・HPを解決する。攻撃側補正は一度だけ適用し、転送中のダメージは再度肩代わりしない。

例えば、通常攻撃10を味方1人のタンクが肩代わりすると、元の対象が5、タンクが自身の20%軽減後の4を受ける。シールド・HP・バリアの容量が十分なら、攻撃者の与ダメージは9。タンクを撃破した場合は元の攻撃者へキルが入り、被ダメージやデスは実際の受け手へ記録する。

状態効果の重複と寿命は[クラス共通能力](class-abilities.md)、集計と通知は[戦闘フィードバックと個人成績](combat-feedback.md)を参照。

## v0.3.4のヘッドレスAI戦比較

`node scripts/simulate.ts` で戦術マップ5種・AI戦略とシード4組の計20試合を比較した。「発射数」は射程内で成立した発射で、同tickで標的が先に撃破されて実ダメージを与えなかったものも含む。

| 指標 | v0.3.3（27 DPS） | v0.3.4（20 DPS） |
| --- | ---: | ---: |
| 発射数 | 26,564 | 42,953 |
| 撃破数 | 967 | 973 |
| 占領完了数 | 976 | 1,004 |
| 平均点差 | 178.6 | 169.4 |
| 青／赤の勝利数 | 9／11 | 9／11 |

10条件で個別の勝者が変化した。初回の発射tickは全20条件で一致した。攻撃の数値だけを変更した版と、ダメージ処理を整理した版の計測出力は全項目で一致した。
