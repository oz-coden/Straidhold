# v0.1.1 視界・カメラ・戦況HUD

## 視界と公開情報

生存中の味方全員の視界を共有する。キャラクターの視界半径は235ワールド単位で、遮蔽物には移動・戦闘と同じ戦場データを使う。攻撃には従来どおり攻撃者自身の見通し、射程、照準方向が必要。AIは従来どおり各ユニット自身の視界で判断する。

| 表示条件 | 内容 |
| --- | --- |
| 常時公開 | 地形、本部、チームスコア、ラウンド残り時間、拠点の所有・装置起動・係争、両チームの生死・復活秒数 |
| チーム共有視界内 | 生存中の敵の位置、戦場での向きと耐久、ターゲットリング、可視端点を持つ弾道 |
| 味方チーム内 | 味方全員の生存中の位置と自分の向き |

共有視界を失った敵は、そのステップで表示対象から外れる。最終確認位置の記録は今回扱わない。弾道は攻撃成立時の座標を保持し、現在の視界から外れたキャラクターの移動には追従しない。復活予定地を敵HUDに表示する機能はない。

## Fogとカメラ

試合中は地形を常時描画し、視界外を約73%不透明の暗いマスクで覆う。遮蔽物との交点まで伸ばした放射線と、壁の角の左右を通る追加の放射線で視界の輪郭を作る。Canvasのアンチエイリアスと縮小マスクの線形拡大で縁をなめらかにする。戦場とミニマップは同じマスクを使う。

敵の表示判定には毎シミュレーションステップの正確な距離・視線を使う。視界ポリゴンは画面を更新するときに必要分だけ計算し、座標・半径が同じキャラクターの輪郭は再利用する。

- カメラはSimpludifyの `CameraFollow` で衝突解決後の自分の位置を即時追従する。短辺は通常517ワールド単位（視界直径470の1.10倍）。
- 横長・縦長の画面では描画領域の比率を1.02〜1.62に収める。マップ端は外側68単位までの余白を許容し、隅でも戦場全体を見渡す表示には切り替えない。
- 死亡時は最後の位置でカメラを保持し、生存中の味方の共有視界を引き続き表示する。復活後は自分へ戻り、再試合時はカメラ・Fogを初期化する。
- マウス照準はSDKの画面・ワールド変換を使う。タッチの操作位置は画面の左右に配置し、カメラの描画幅に連動させない。

## ミニマップと戦況HUD

ミニマップは全体の壁・通路・本部、拠点A・B・C、所有状態と進捗、味方の丸、自分の向きを示す白い矢印、視認中の敵のひし形、カメラ枠を表示する。拠点は中立・青・赤を線幅・実線・破線でも区別し、係争は交差印で示す。

戦況HUDは両チーム5人ずつの生存アイコンと生存人数を表示する。死亡した枠の数字はシミュレーションの復活時刻までの残り秒数。拠点欄では所有チーム、起動中のチーム、係争と起動進捗を文字・アイコン・進捗バーで確認できる。

## 対応と今後

キーボード・マウス、スマートフォンの横画面タッチ、標準マッピングのゲームパッドに対応する。Chromiumでデスクトップ、縦長・横長のViewport、568×320の同時タッチ、ゲームパッドの模擬入力を検証対象とする。実機のモバイル端末と物理ゲームパッド、Safari・Firefox、低性能機でのフレームレートは今後の検証項目。

ローカル試作ではブラウザが全参加者をシミュレートする。オンライン化では、権威サーバーが公開情報とチームごとの可視情報に絞って配信する設計が必要。ミニマップでのピン・操作、最終確認位置、茂みなどの追加視界ルールは今後の検討範囲。

Simpludifyの改善候補は、Tilemapの線分と最初の遮蔽物の交点を返すAPI、ワールド座標での任意マスク描画、描画直前・直後にHUDの投影を更新できる公開フック。現在はSDKのカメラ・座標変換と `FrameDriver` を利用し、Fogを標準Canvas 2Dで合成している。

[v0.1.2](../CHANGELOG.md#012)では、視界・攻撃・Fogの線分判定をSimpludify v0.3.0のレイキャストに移行した。
