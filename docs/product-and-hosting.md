# 配布・ゲームモード・オンライン運用方針

> **状態：** 将来の製品化に向けた方針と検討事項。v0.1.0で実装済みの機能を示すものではない。販売価格、無料体験版の制限値、公式サーバーの提供規模、課金特典等は未決定。

## 製品の基本方針

Straidholdは**買い切りのゲーム本体**を中心に提供する。公式オンラインサービスの利用を製品価値の前提とせず、購入後は外部の認証サーバーや公式ゲームサーバーに依存せずに遊べる構造を目指す。

- ソロ向けコンテンツ、オフラインAI対戦、繰り返し遊べるエンドコンテンツを提供する。
- プレイヤー同士のオンライン対戦は、公式・ユーザー運営を問わず独立したゲームサーバーへの接続で実現する。
- 専用サーバープログラムは無料配布を想定する。ゲーム本体のクライアントは有料とし、独自のアカウント登録・常時オンライン認証・強いDRMは原則設けない。
- 製品版はユーザーがサーバーを追加し、セルフホスト環境を利用できる。公式サーバーが停止してもマルチプレイヤー機能を失わないことを目標とする。
- ソースコードの秘匿よりも開発・保守性を優先し、配布クライアントには通常の最適化・Minifyを基本とする。高度な難読化は前提にしない。

具体的な配布ストア、プラットフォーム、価格、ライセンス条件は将来決定する。ゲームエンジンSimpludifyと製品Straidholdの配布条件は分けて扱う。

## ソロ・オフラインコンテンツ

オフラインプレイを主たる価値の一つとし、次のコンテンツを検討する。

- **キャラクター別ストーリー：** 各キャラクターの人物像や背景を紹介し、固有能力・操作方法を学べる短編。
- **メインストーリー：** 対戦用の基礎システムを再利用しつつ、改造したマップや専用ミッションを攻略して物語を進めるステージ制キャンペーン。オープンワールドは想定しない。
- **オフラインAI対戦：** 人間とAIが同じルールで参加する5対5の対戦。人数不足をAIで補う仕組みを活用する。
- **エンドコンテンツ：** クリア後も繰り返し遊べる内容を用意する。AIスカーミッシュ、チャレンジ、周回型ミッションなどは候補であり、形式は未決定。

ストーリーは単なる対戦チュートリアルの連続ではなく、ソロで楽しめる独立したモードとして提供する。戦闘・移動・AIなどの共通機構は再利用し、モード固有の勝利条件と進行管理を分離する。

## マルチプレイヤーとサーバー

### 接続先の管理

マルチプレイヤーの基本操作は、プレイヤーがサーバーのホスト名または接続先を自分で登録して接続する方式とする。中央のサーバーディレクトリやアカウントサービスへの依存は前提にしない。

公式サーバーはクライアントに**初期登録された接続先**という位置づけであり、接続のための特別なゲームプロトコルを持たせない。公式サーバーが利用できない場合は一覧から非表示にする案がある。公式接続先の詳細は通常のUIでは表示しない方針だが、クライアントが接続する以上、実際の接続先を技術的に秘匿できるわけではない。

公式接続先には `straidhold.oz-coden.com` などの管理ドメインを使用する案がある。運用環境を変更した場合も、原則としてDNSを更新して移行できる設計とする。稼働判定はDNS解決と区別し、軽量なステータス確認で行う。DNSの反映遅延や通信方式に応じたプロキシ設定は実装時に確認する。

### セッションの独立性

オンラインサーバーの主たる責務は、**各ゲームセッションの開始から終了まで**を管理すること。

- 参加者の接続・切断・参加枠、AI補充、セッションの生成・終了を管理する。
- サーバー権威型のシミュレーションで移動、攻撃、スキル、経済、占領、勝敗などを確定する。クライアントは操作命令のみ送り、不正な状態変更要求は採用しない。
- 通信入力は所有するキャラクターにのみ適用し、形式・頻度・順序・範囲などを検証する。
- セッション終了後の状態は原則破棄し、独自アカウント、クラウドセーブ、中央ランキングなどの恒久管理を必須にしない。
- サーバーの管理者によるルール変更・MOD・チート相当の改造はセルフホストで許容する。公式サーバーは標準ルールと公平性を維持する。いずれの場合もクライアント申告のダメージやHP等を信用しない。

権威型であっても、正常な操作命令を装うエイムボット等を自動的に防げるわけではない。追加の不正対策の水準は公式運用時に判断する。通信設計の詳細は[ネットワークとシミュレーション](networking.md)を参照。

### 2種類のホスト

- **クライアント内蔵ホスト：** プレイヤー本人が参加するセッションを端末上で開催する。原則1セッション程度の軽量な利用を優先する。
- **専用サーバー：** 描画なしで独立実行できる無料のサーバープログラム。管理者が環境の能力に応じて同時セッション数やルールを設定できる。プレイヤー自身がサーバープロセスに参加する必要はない。

両方式で共通のゲームルール・権威モデルを利用し、実行方式を切り替えられる構成を目指す。セルフホストに必要な直接接続・LAN接続等は、公式サーバーや中央認証への依存なしに動作することを目標とする。NAT越え、モバイルOSの制約、ブラウザの通信制約は別途検証する。

### 公式サーバーの運用

公式サーバーは、参加者が気軽に対戦できる便宜的な接続先であり、永続提供を保証する前提にはしない。

- 同時に稼働するセッション数に上限を設け、満室時には待機キューで受け付ける案を採る。
- 待機状態（順番、待機人数、参加可能状態）は十数秒間隔のポーリングなどで低負荷に取得する案がある。満席時の入場通知、待機チケットの失効、切断時の復帰は別途設計する。
- 小規模な初期運用は既存のOracle Cloud環境や、将来確保するA1 Flexなどを候補とする。ただし同時セッション数はCPU・メモリ・遅延の実測で決定し、無料枠の確保を実装の必須条件にしない。
- 負荷や売上に応じて、独立した有料ホストへ移行できるようにする。公式サーバーが満室・停止中でも、ソロモードとユーザー運営サーバーを利用できる構造を維持する。

## 無料体験版

無料体験版を提供し、ゲーム本体とオンラインの基本的な楽しさを試せるようにする。

| 項目 | 無料体験版の方針 | 製品版の方針 |
| --- | --- | --- |
| ストーリー | 一部ステージ・キャラクター編を収録 | 全編を提供 |
| オフラインAI対戦 | コンテンツや利用回数等に制限を設ける案 | 制限なし |
| 公式オンライン | 指定した体験枠で参加可能 | 通常参加 |
| ユーザー指定サーバーへの接続 | 提供しない | 対応 |
| 内蔵セルフホスト | 提供しない | 対応 |
| 専用サーバーの利用 | 公式のみ接続可能 | 自由に接続・設置可能 |
| アカウント認証 | 必須としない | 必須としない |

体験版のオンライン参加回数に上限を設ける場合、**セッションへの参加が確定した時点で1回消費**する。正常終了・勝敗・途中切断による払い戻しを原則設けず、待機キューに入っただけでは消費しない。

回数や進行状況は、体験版のローカルデータ（WebではLocalStorage、アプリ版ではローカル保存領域等）に記録する案を採る。削除・改ざんで回避できることは許容し、厳格なDRMやアカウント認証を追加しない。体験版の接続制限も、改造クライアントに対する強固なサーバー側証明を前提としない。

ダウンロード数の節目やイベント時に体験回数を追加・リセットする案は**任意の検討項目**とし、そのためだけに恒久的なオンライン基盤を導入しない。初期回数、上限、配布条件、製品版の待機優先順位の扱いは未決定。

### セーブデータの引き継ぎ

体験版の操作設定やストーリー進行は、可能な範囲で製品版へ引き継げるよう共通のデータ形式を検討する。自動移行は必須にしない。

- Web体験版からデスクトップ・モバイル製品版への移行には、セーブデータのエクスポート／インポートが候補となる。
- 入力ファイルは形式・バージョン・内容を検証し、破損時の復旧や既存データの保護を考慮する。
- オンラインの一時的な試合状態をセーブデータへ移すことは想定しない。サーバーは原則セッション終了で試合状態を破棄する。
- 体験版の残り回数を製品版へ引き継ぐ必要はない。

データ移行の実装・検証負担が大きい場合は、提供時期や対象データを絞る。進行形式や保存仕様はストーリーモード実装時に確定する。

## 追加の収益手段

買い切り販売を基本とし、任意の支援・スポンサー制度、外観アイテム、追加コンテンツ等は将来の選択肢として残す。サブスクリプションは運営負担と維持コストを比較して判断し、必須の継続課金にしない。

公式オンラインの利用に追加課金を必須とする方針ではない。公式サーバー費用をゲーム本体の売上だけで永続的に賄えると仮定せず、サーバーの停止や移転が可能な運営形態を維持する。
