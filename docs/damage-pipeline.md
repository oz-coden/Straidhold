# 通常攻撃とダメージ処理

## 共通通常攻撃

試作版の共通通常攻撃は、60Hzの固定ステップで1発10ダメージ、30tick（0.5秒）間隔。入力保持かつ攻撃対象が有効な状態での基準値は20 DPS。基本HPと通常シールドは各100。照準方式、射程、視界、遮蔽物は既存の戦闘ルールに従う。キャラクター固有の攻撃は個別の設計値を使う。

## 処理の順序と責務

1. `DamageRequest` にラウンド内の攻撃識別子、元の攻撃者、元の対象、基礎ダメージを記録する。
2. `DamageContext` をリクエストから初期化し、今回の適用先と現在のダメージ量を持たせる。効果を実装する際は、ここでバフ・デバフを補正する。効果の寿命や参加者の状態は戦闘側が保持する。
3. 特殊処理は補正後に **特殊バリア → 肩代わり → 将来追加する特殊処理** の順で適用する。各処理の順序は実装側で明示し、効果の登録順には依存させない。
4. `resolveDamage` が通常シールドを減らし、超過分をHPへ適用する。入力のContextと対象の現在値から、実際に減少した量・適用先・適用後の値・撃破の有無を `DamageResult` として返す。
5. `Battle` が結果を対象に反映し、実ダメージを被ダメージ統計、アシスト履歴、命中イベントに渡す。HPが0になった一撃で撃破を確定する。死亡済みの対象や実減少のない適用では、通常シールド・HPの命中を記録しない。

現在の試作版は、補正と特殊処理の境界を通ってシールドとHPを解決する。各tickで攻撃を先に全員分集めるため、そのtickに撃破された攻撃者の発射も着弾し、相互撃破が成立する。回復は着弾後に処理し、実際に回復が始まった時点でアシスト履歴をクリアする。命中・撃破イベントは[戦闘フィードバックと個人成績](combat-feedback.md)の集計に使う。

## バフ・デバフの重複規則（実装方針）

- 同名の効果は原則として最も強いものだけを適用する。個々の効果の有効期限は保持し、最も強い効果が終了したら、まだ有効な次に強い効果を適用する。
- 異名の効果は原則として重複できる。層設計を明示した能力は、その能力で定めた条件に従ってスタックする。
- 効果量は原則として上限を設けない。移動速度など負数が成立しない値は0を下限とする。
- コントロール・サポートのチームパッシブも同名非重複とする。自身を発生源とする分は自身から除外し、他の味方が発生源であれば適用候補になる。同クラスが複数いても、同名の効果は1件だけ有効。

## 特殊バリアと肩代わり（実装方針）

特殊バリアの吸収を先に判定し、肩代わりはその後に届く一次ダメージに適用する。転送先では、元の `DamageRequest` を参照する別のContextを作り、実際の受け手と転送済みであることを保持する。元の攻撃識別子、攻撃者、攻撃対象を維持する。

転送量は元の攻撃の与ダメージ補正を適用済みと扱う。転送先の被ダメージ軽減を適用し、攻撃側の与ダメージ増加は再適用しない。転送されたダメージは再度肩代わりできない。撃破は元の攻撃者へ、被ダメージは実際に受けた参加者へ計上する。

反射・連鎖など派生処理を追加する場合は、同じ攻撃識別子の中で再適用を禁止する処理をContextで識別し、派生回数または処理済みの適用経路を有限に制限する。各処理に明示的な終端を定義してから追加する。バリア固有の吸収量、通常シールドの回復待ちや命中への反映は、特殊バリアの実装時に結果へ追加する。

## ヘッドレスAI戦の比較

`node scripts/simulate.ts` で戦術マップ5種・AI戦略とシード4組の計20試合を比較した。「発射数」は射程内で成立した発射で、同tickで標的が先に撃破されて実ダメージを与えなかったものも含む。

| 指標 | v0.3.3（27 DPS） | v0.3.4（20 DPS） |
| --- | ---: | ---: |
| 発射数 | 26,564 | 42,953 |
| 撃破数 | 967 | 973 |
| 占領完了数 | 976 | 1,004 |
| 平均点差 | 178.6 | 169.4 |
| 青／赤の勝利数 | 9／11 | 9／11 |

10条件で個別の勝者が変化した。初回の発射tickは全20条件で一致した。攻撃の数値だけを変更した版と、ダメージ処理を整理した版の計測出力は全項目で一致した。
