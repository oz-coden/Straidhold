## AI戦の比較

各版で同じAI・60Hz・5分間・4通りの戦術を使い、各戦場4試合を実行した。交戦は同じ敵味方の組が3秒以上空けて攻撃を命中させた回数。無交戦は初回命中後の最長時間で、最後の命中から試合終了までを含む。

| 戦場 | 初回命中の平均（秒） | 交戦 | 最長の無交戦（秒） | 再占領 | 補給切断 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 両側分岐 | 12.0 → 9.2 | 503 → 683 | 11.7 → 8.4 | 145 → 176 | 185 → 246 |
| 中央三拠点 | 14.6 → 11.9 | 461 → 597 | 14.0 → 13.1 | 161 → 178 | 218 → 238 |
| 中央防衛線 | 12.1 → 9.3 | 542 → 672 | 14.9 → 10.8 | 135 → 165 | 145 → 180 |
| 分岐と合流 | 11.3 → 8.5 | 759 → 886 | 12.7 → 10.7 | 145 → 158 | 162 → 188 |
| 交差補給路 | 12.4 → 9.7 | 465 → 624 | 16.5 → 9.4 | 145 → 179 | 289 → 348 |

縮小後は全試合で各分に命中が発生し、移動コマンド中のジャングル利用率は戦場別に約35〜45%だった。20試合を再実行した際の出力は一致した。マップ検証では占領範囲の非重複、レーン中心線の衝突余白、外周の迂回、壁を回る経路探索を確認する。勝率は各戦場4試合でAIの戦術に依存する。

`npm run simulate --silent` で試合別の交戦、拠点、補給、経路を出力する。[v0.2.1の計測方法](prototype-v0.2.1.md)と共通で、比較元はコミット `260e2b4bd087998eda3bf94cc5d4863dac040075`。

## タッチ入力中断の調査と修正

v0.2.1の中央防衛線で、移動中に別の指で装置を設置すると再現した。Chromiumの568×320、390×844、700×320で、装置の起動テキストが拠点HUDの狭い列で折り返され、戦場の高さを変えていた。568×320では戦場が131pxから97px、操作ホストが129pxから95pxになった。最初の指には `pointerup`、`pointercancel`、`lostpointercapture` が発生せず、入力モードもタッチのままだった。エンジン内部では `VirtualInput.refresh()` がスティックの有効化領域の実際の変化を検知し、`VirtualControl.invalidate()` がそのジェスチャーを解除していた。

Straidholdの拠点表示を1行にし、設置チームと進捗を短く表示した。詳細は進捗バーとラベルに残す。アクション欄は空欄を含む3行の高さを確保し、文字の更新で戦場サイズが変わらないようにした。実際のリサイズで領域が変わったときのキャンセルには、Simpludify 0.3.0の公開仕様を使う。

ブラウザの回帰テストは別々のタッチIDで操作し、設置前から得点と補給接続が更新されるまで最初の指を離さない。戦場のサイズと移動の継続を検証し、リリース後に停止することも確認する。
